Nest 11.2.12, Throttler 6.8.0, Prisma 7.10.1, file-type 21.3.4를 설치했습니다. 메일은 Resend를 사용하므로 쓰이지 않는 Nodemailer와 타입 패키지를 삭제했습니다. Prisma CLI의 `effect`와 `ajv`의 `fast-uri`를 해당 메이저 안에서 패치했습니다. Firebase Admin 13을 유지하고 `gaxios`, `google-gax`, `teeny-request`의 `uuid`만 11.1.1로 올렸습니다. 세 패키지가 호출하는 `uuid.v4()`를 CommonJS에서 확인했습니다.

전체 감사의 남은 항목은 Jest 및 Nest CLI의 `glob`과 `minimatch` 전이 의존성에서 발생합니다. npm의 강제 수정안에 Nest CLI 12가 포함되어 있어 Nest 11 환경에서 보류했습니다.

## 엔드포인트 검토

| 엔드포인트 | 검토 결과 및 변경 |
| --- | --- |
| 인증 및 FCM | 공개 가입·로그인·인증·재발송에 기존 요청 제한을 유지했습니다. 로그인과 갱신 토큰을 분리하고, 로그아웃·FCM은 액세스 토큰을, 갱신은 리프레시 토큰을 요구합니다. 이메일 인증은 DB 상태를 한 번만 바꾸며 신규 비밀번호는 bcrypt의 72바이트 한도를 적용합니다. |
| 찬양 및 악보 | 찬양 목록은 공개 곡과 본인 곡으로 제한됩니다. 상세는 공개 또는 소유권, 수정·삭제는 소유자 또는 관리자, 공용 악보 변경은 관리자 권한을 검사합니다. 관리자 여부는 요청 시 DB에서 읽습니다. |
| 콘티, 곡, 콘티 악보 | 소유자 또는 현재 공유 팀원만 상세 조회·복제가 가능합니다. 곡 수정·삭제·정렬에 콘티 ID를 함께 검증하고, 추가는 공개 곡 또는 본인 곡으로 제한했습니다. 곡 변경은 트랜잭션에서 처리합니다. 악보 변경은 기존 콘티·곡·악보 소유권 검사를 확인했습니다. |
| 히스토리 | 조회·삭제는 본인 기록으로 한정됩니다. 접근 가능한 콘티만 연결할 수 있고, 기존 기록도 현재 접근 권한이 없으면 중첩 `conti`를 `null`로 반환합니다. |
| 팀·초대·채팅 | 가입 링크와 이메일 초대의 유효기간 및 대상, DB 기준 팀 역할을 확인했습니다. 이메일 초대 응답을 트랜잭션으로 처리합니다. 방·팀 SSE는 연결 시와 메시지 전송 전에 멤버십을 확인하고 토큰 만료 시 종료합니다. 메시지 삭제는 해당 방의 현재 멤버이면서 작성자인 사용자만 가능합니다. |
| 게시글 및 댓글 | 목록과 댓글 조회는 공개입니다. 작성·삭제는 인증을 요구하며 삭제는 작성자 및 상위 게시글을 검사합니다. 새 게시글에 타인의 묵상을 연결할 수 없습니다. 익명 글과 댓글 응답의 `userId`는 다른 조회자에게 빈 문자열을 반환하며 익명 글의 `meditationId`는 `null`로 반환합니다. |
| 성경, Spotify, 헬스 | 무작위 성경 구절과 헬스는 공개입니다. 개인 묵상과 성경·Spotify 검색은 인증이 필요하고, 묵상 수정은 사용자 ID로 제한됩니다. 기본 `AppController`는 운영 모듈에 등록되어 있지 않습니다. |
| 첨부 업로드 | 인증, 파일 하나, 디스크 임시 저장과 정리를 확인했습니다. 악보는 10 MiB, 일반 업로드는 50 MiB 제한을 유지합니다. 선언 MIME과 파일 시그니처를 대조하며 새 첨부 링크와 기존 첨부 조회는 HTTP(S)만 허용합니다. |

JWT는 최소 32바이트의 서로 다른 키와 HS256을 사용합니다. 기본 만료는 액세스 15분, 리프레시 30일이며 저장 TTL은 리프레시 만료와 같습니다. 리프레시 토큰 전체를 SHA-256으로 비교하고 Redis에서 원자적으로 교체합니다. 배포 이전 bcrypt 방식으로 저장된 리프레시 토큰은 사용할 수 없어 기존 사용자가 한 번 다시 로그인해야 합니다.

API에 Helmet을 적용했고, CORS는 `CLIENT_URL` 목록과 일치하는 출처에 허용 헤더를 보냅니다. DTO에 선언되지 않은 본문 필드는 거부합니다. 잘못된 JSON과 내부 예외는 일반 오류로 반환하고, 메일·Redis·Firebase·파일 관련 로그에서 원문 예외와 FCM 토큰을 제거했습니다. 메일 HTML의 사용자 입력을 이스케이프합니다.

## 운영에서 결정할 항목

- 이제 `HOST` 기본값은 모든 환경에서 `127.0.0.1`입니다. Oracle VM에서는 환경 설정 누락에도 안전한 코드 기본값을 권장하며, nginx 뒤에서는 `NODE_ENV=production`과 루프백 프록시를 유지하는 것이 적절합니다. 개발 기기의 LAN 접속이 필요할 때 `HOST=0.0.0.0`으로 열 수 있습니다.
- 키 교체는 두 키를 각각 생성하고 재로그인 시간을 잡는 방식입니다. 이번 배포에도 리프레시 저장 형식이 바뀌며, 웹·앱에서 동시에 갱신하면 한 요청만 성공하도록 서버가 처리합니다. 클라이언트 단일 갱신 처리와 여러 기기별 세션을 지원할지는 별도 제품 결정입니다.
- 기존 SSE와 이메일 인증의 URL 토큰을 계속 지원합니다. SSE 쿼리 토큰은 두 SSE 경로에서만 인정합니다. 운영 nginx 로그에서 토큰이 들어가는 경로의 쿼리나 초대 경로 토큰을 기록할지, 추후 URL 토큰을 제거할지는 배포 설정과 클라이언트 변경이 필요합니다.
- 가입·인증 재발송 응답을 이용하면 이메일 가입 여부를 추측할 수 있습니다. 현재 웹·앱 오류 동작을 유지했습니다. 공개 커뮤니티·헬스·무작위 구절, 팀원 간 이메일 표시 여부, 공개 URL로 전달되는 업로드 파일의 비공개 전환도 서비스 정책에 따라 결정해야 합니다.
- 기존에 저장된 콘티와 찬양 연결은 정상 복제 또는 공유로 만들어졌을 수 있습니다. 기존 비공개 곡 연결의 정리가 필요한지는 운영 데이터 검토 후 결정해야 합니다. 외부 메일·FCM 발송, 운영 nginx·Redis·Postgres 연동은 로컬 검증 범위 밖입니다.
